# Арена переговоров

Веб-тренажёр деловых переговоров: участник выбирает ситуацию, ведёт диалог с виртуальным оппонентом и получает разбор с оценкой по конкретным репликам. Тренировку можно повторить на тех же условиях и сравнить результат. Проект создан для ЛЦТ 2026.

Работающая версия: [нии-гараж.рф](https://нии-гараж.рф/).

## Возможности

- Сценарии переговоров с настраиваемыми условиями и сложностью.
- Текстовый диалог, голосовой ввод и режим звонка.
- Автоматический отчёт с оценкой, цитатами и рекомендациями.
- Анонимная взаимная проверка переговоров и сравнение повторных попыток.
- Личный кабинет, карта навыков и тренировочные задания.

Взаимная проверка вдохновлена учебной моделью «Школы 21»: после автоматического отчёта участник разбирает чужой анонимизированный диалог по той же рубрике и получает обратную связь о качестве своей проверки. Это самостоятельный проект, не связанный со Сбером или «Школой 21».

Исход переговоров и баллы рассчитывает серверный движок по правилам сценария. Gemini, если настроен, помогает формулировать реплики и пояснения, но не меняет правила и оценку. С пустым API-ключом текстовая тренировка и отчёт работают во встроенном резервном режиме; функции, которым необходим голосовой сервис Gemini, без ключа недоступны.

## Структура проекта

| Путь | Назначение |
| --- | --- |
| `apps/web` | Интерфейс на Next.js 15, React 19 и TypeScript |
| `apps/api` | API на FastAPI и Python 3.12, движок переговоров, отчёты и миграции Alembic |
| `apps/api/scenarios` | Конфигурации переговорных сценариев |
| `apps/api/golden_dialogues` | Эталонные диалоги для проверки методики |

Для локального запуска используется PostgreSQL 16 из `compose.yaml`; структуру базы создают миграции Alembic.

## Локальный запуск

Понадобятся Python 3.12, Node.js 22 с npm, а также Docker с Compose v2. Команды ниже рассчитаны на чистое клонирование репозитория: локальная база использует значения по умолчанию из `compose.yaml`. Ключ Gemini для базовой текстовой тренировки не нужен.

### 1. Запустите PostgreSQL

Из корня репозитория:

```bash
docker compose up -d --wait postgres
```

Compose создаст контейнер PostgreSQL 16 и дождётся его готовности. Данные сохраняются в Docker volume между запусками.

### 2. Запустите API

Windows PowerShell:

```powershell
cd apps/api
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
$env:DATABASE_URL = "postgresql+psycopg://arena:arena_local_only@localhost:5432/arena"
.\.venv\Scripts\alembic.exe upgrade head
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Linux/macOS:

```bash
cd apps/api
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -e .
export DATABASE_URL="postgresql+psycopg://arena:arena_local_only@localhost:5432/arena"
alembic upgrade head
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Проверка API: <http://127.0.0.1:8000/health/ready>; интерактивная документация: <http://127.0.0.1:8000/docs>.

### 3. Запустите интерфейс

В отдельном терминале, из корня репозитория:

```bash
cd apps/web
npm ci
npm run dev
```

Откройте <http://localhost:3000>. Интерфейс обращается к API через прокси Next.js на `127.0.0.1:8000`.

## Конфигурация и проверка

В `.env.example` поле `GEMINI_API_KEY` намеренно пустое. Для локального запуска выше файл `.env` создавать не требуется. Если нужен доступ к Gemini, задайте свой ключ только в локальном окружении API; не добавляйте его в репозиторий и не используйте переменные `NEXT_PUBLIC_*` для секретов.

Проверить код можно командами `npm run typecheck` и `npm run build` в `apps/web`. Для тестов API установите зависимости разработки через `python -m pip install -e ".[dev]"` в `apps/api`, затем выполните `python -m pytest`.
